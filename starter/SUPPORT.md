| ------------------------------------------ | ----------------------------------------------------- |

| Report behavior that differs from the docs | Open a bug report from the issue templates            |
| Propose a change                           | Open a feature request from the issue templates       |
| Report a security vulnerability            | Follow [SECURITY.md](SECURITY.md), not a public issue |
| Contribute code                            | Read [CONTRIBUTING.md](CONTRIBUTING.md)               |

## Before you ask

- Search open and closed issues.
- Check the [changelog](CHANGELOG.md) for a fix in a newer version.
- Collect the version, your environment, and the exact steps. A report with those is usually
  reproducible in one try; a report without them usually needs a conversation first.

## In scope

- Defects in {project name}.
- Questions about its design and use.

## Out of scope

- Problems in your own fork, data, or environment where {project name} is not at fault.
- Guaranteed response times. {State whether a paid support option exists.}
- Anything that needs confidential data. Never paste secrets or private data into a public
  thread.

## What to expect

- Issues are read {how often}. Being read is not the same as being fixed.
- Reports with reproduction steps are looked at first.
- Security reports follow the timeline in [SECURITY.md](SECURITY.md).
